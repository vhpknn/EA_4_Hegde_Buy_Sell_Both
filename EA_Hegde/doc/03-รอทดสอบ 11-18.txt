


วิธีทดสอบและผลคาดหวังของแต่ละชุด โดยแยกสิ่งที่ทำได้ทันทีออกจากสิ่งที่ยังต้องเตรียมก่อน

SHORT_11 — Report / Recovery / Failure
ไฟล์: SHORT_11_REPORT_DEMO.set

ค่าหลัก: Magic 99911, Report เปิด, ReportDays=1, Auto Reopen ปิด, Lot คงที่ 0.01 และทุนเริ่มต้นเสมือน 50

เป้าหมายและขั้นตอน
ชุดนี้มีสามสถานการณ์แยกกัน ไม่ใช่โหลดไฟล์แล้วกด HEDGE ครั้งเดียวจะครบทั้งหมด

สถานการณ์	วิธีทดสอบ	ผลที่คาดหวัง
สร้างรายงานปกติ	ให้รอบ Report ถึงกำหนดและ Basket ว่าง	สร้าง CSV สมบูรณ์ มี TOTAL และ REPORT_COMPLETE แล้วปลด Report Gate
Recovery	เตรียม CSV ที่สมบูรณ์ของ Demo Scope นี้ แต่ State ยังชี้รอบเดิม	พบ Recover Completed Report ใช้เวลา End เดิม ไม่สร้างรายงานรอบเดิมซ้ำ
Failure	เตรียมไฟล์รายงานปลายทางของรอบนั้นที่ผิดรูปแบบ	ไม่เขียนทับไฟล์เดิม และไม่อนุญาตเปิดคู่ผ่าน Report Gate
เงื่อนไขเหล่านี้ตรงกับคำอธิบาย Preset และกรณี Report ใน Checklist ครับ

ระยะเวลาและข้อจำกัด
การโหลด .set อย่างเดียวไม่ได้ทำให้ Report ถึงกำหนด

การทดสอบ SHORT แบบไม่รอหนึ่งวัน ต้องเตรียมเวลาเริ่มรอบ RPD ของ Magic 99911 ให้เหมาะสม พร้อมสำรอง State และตรวจชื่อไฟล์ก่อน

Recovery ต้องมี CSV ที่สมบูรณ์ของ Demo Scope นี้ก่อน ไม่ใช้ไฟล์จาก Tester มาแทน

ตอนนี้ยังไม่ควรแก้ RPD หรือตั้งไฟล์เสียโดยเดาชื่อ เพราะเอกสารที่แนบมายังไม่ได้ระบุ Key และไฟล์จริงสำหรับบัญชีคุณ

เก็บหลักฐาน: Inputs, เวลา Server, Experts, CSV และภาพ/ค่าของ RPD ก่อน–หลัง

เกณฑ์จบ: ตัดสินแยกสามสถานการณ์ ถ้าทำเพียงรายงานปกติ ห้ามนับ Recovery/Failure ว่าผ่านด้วย

SHORT_12 — Capital Zero
ไฟล์: SHORT_12_CAPITAL_ZERO.set

ค่าหลัก: Magic 99912, Initial Capital=0, Auto Reopen เปิด, Timeout=300 วินาที, Spread Check=25, Report ปิด

ขั้นตอน
เริ่มขณะไม่มี Position ของ Symbol + Magic 99912

โหลด Preset แล้วตรวจ Virtual Equity จริง ต้องไม่เกิน 0

ตรวจว่าไม่มี REFILL หรือ Closed Net เดิมของ Scope นี้ทำให้ทุนกลับเป็นบวก

สังเกต Auto และเก็บเหตุผลที่ถูกบล็อก

กด HEDGE หนึ่งครั้งเพื่อตรวจ Manual Capital Gate โดยยังไม่กด REFILL

ผลคาดหวัง
Auto ไม่เปิดคู่เมื่อทุนไม่พอ

HEDGE ไม่เปิดคู่เช่นกัน

มีหลักฐานเหตุผลเรื่องทุน ไม่ใช่สรุปจาก “ไม่มี Order” อย่างเดียว เพราะ Timeout/Spread อาจบล็อกอยู่ด้วย

Initial Capital=0 แต่ Virtual Equity เป็นบวกจากข้อมูลเดิม ถือว่าเตรียมเงื่อนไขไม่สำเร็จ ไม่ใช่ผล FAIL ของ Capital Gate

ระยะเวลา: ไม่ต้องรอข้ามวัน หากพิสูจน์ Auto หลัง Timeout ต้องสังเกตจนพ้น 300 วินาทีและแยก Gate อื่นให้ชัด

เก็บหลักฐาน: Inputs, Virtual Equity, Closed Net/REFILL ที่เกี่ยวข้อง, Experts และรายการ Position

หมายเหตุ: ชุด Basket ว่างนี้ยังไม่พิสูจน์ว่า Protection/คำสั่งปิดทำงานต่อเมื่อทุนหมด ต้องมีอีกสถานการณ์ที่มี Position อยู่ก่อนครับ

SHORT_13 — Auto-Lot
ไฟล์: SHORT_13_AUTOLOT.set

ค่าหลัก: Magic 99913, Auto-Lot เปิด, Initial Capital=50, Base Lot=0.01, Lot Step Money=50, Lot Increment=0.01, Max Lot Step=4 และ Auto Reopen เปิด

ขั้นตอน
โหลด Preset ขณะ Scope นี้ไม่มี Position

เก็บภาพ Virtual Equity, Effective Lot และ Inputs

รอ Auto เปิดคู่ ไม่กด HEDGE เพื่อแทนการตรวจ Auto

เทียบ Volume จริงของ Buy และ Sell กับ Effective Lot

ถ้าจะตรวจบันไดครบ ต้องมี Variant หลายระดับทุน โดยเปลี่ยนขณะ Basket ว่างและบันทึกทุนเริ่มต้น + REFILL + Closed Net ทุกครั้ง

ผลคาดหวัง
Volume ของทั้งสองขาเท่ากัน และตรง Effective Lot ที่คำนวณได้

Lot ตรงข้อจำกัด Volume ของ Symbol

เมื่อทดสอบหลายระดับทุน ผลต้องตรงสูตรบันไดและเพดาน

รันค่าทุนระดับเดียวผ่าน ไม่ได้แปลว่าบันไดและเพดานครบทุกระดับผ่านแล้ว

ระยะเวลา: จบการตรวจค่าตั้งต้นได้เมื่อเปิดคู่และเทียบ Lot ครบ ไม่ต้องรอข้ามวัน ส่วนการตรวจหลายระดับต้องแยก Variant

เก็บหลักฐาน: Inputs, Virtual Equity/Effective Lot ก่อนเปิด, Volume จริง และ Experts

SHORT_14 — SL หาย
ไฟล์: SHORT_14_MISSING_SL.set

ค่าหลัก: Magic 99914, Auto Reopen ปิด, Cut Loss=70, BE Trailing เปิดที่ Trigger=120, Step=10, Lock=20%, RR และ Trailing TP ปิด

ขั้นตอน
ใช้ Demo เท่านั้น โหลด Preset แล้วเปิดคู่ด้วย HEDGE

เก็บ Ticket, ราคาเข้า และ SL เดิม

เตรียม Fixture ให้ SL หายทีละ Position ของ Magic 99914 เท่านั้น

แยกตรวจสองสถานการณ์:

กำไรยังไม่ถึง BE Trigger

กำไรเลย BE Trigger แล้ว

เก็บหลักฐานว่า EA พยายามติดตั้ง SL กลับ และ Broker ยอมรับหรือปฏิเสธอย่างไร

ผลคาดหวัง
SL หายก่อน Trigger: EA พยายามติดตั้ง Cut Loss กลับ

SL หายหลัง Trigger: ต้องยังมีเส้นทางป้องกัน ไม่ปล่อยให้เงื่อนไข BE ทำให้ข้ามการติดตั้ง SL

ตรวจทั้ง Buy และ Sell ไม่ใช้ผลฝั่งเดียวแทนอีกฝั่ง

หาก Broker ปฏิเสธ ต้องบันทึกเป็นเหตุ Reject จริง ไม่อ้างว่าติดตั้งสำเร็จ

ระยะเวลา: ขึ้นกับราคาว่าถึง Trigger หรือไม่ ไม่กำหนดว่าต้องรอ 24 ชั่วโมง ถ้าไม่เกิดสถานการณ์หลัง Trigger ให้ระบุว่ายังไม่ครอบคลุม

ข้อควรระวัง: เตรียมวิธีปิด Position ถ้าติดตั้ง SL คืนไม่ได้ก่อนสร้าง Fixture และอย่าปิด Algo Trading ระหว่างตรวจ เพราะ EA ต้องส่งคำสั่ง Modify/Close ได้

เก็บหลักฐาน: Ticket + SL ก่อนหาย/ขณะหาย/หลังคืน, ราคาขณะทดสอบ, Experts และ History

SHORT_15 — Invalid BE Step
ไฟล์: SHORT_15_INVALID_BE_STEP.set

ค่าหลัก: Magic 99915, BE Trailing เปิด แต่ BE Step=0 โดยเจตนา

ขั้นตอนและผลคาดหวัง
จบ Position ของชุดก่อนหน้าให้เรียบร้อย

โหลด Preset แล้วกด OK หรือเริ่ม Tester

ต้องถูกปฏิเสธตอน Init เพราะค่า Step ไม่ถูกต้อง

ต้องไม่มี Order ใหม่จากการทดสอบนี้ ไม่ต้องกด HEDGE หรือ REFILL

ระยะเวลา: จบเมื่อได้ผล Init และข้อความเหตุผล ไม่ต้องรอราคา

เก็บหลักฐาน: Inputs ที่แสดง Step=0 และ Experts/Journal ที่แสดง Init rejection

ถ้า EA เริ่มทำงานปกติทั้งที่ใช้ BE Trailing และ Step=0 จริง ถือว่าผิดจากผลคาดหวังครับ

SHORT_16 — Invalid Trailing Pullback

ระยะเวลา: จบเมื่อได้ผล Init และข้อความเหตุผล

เก็บหลักฐาน: Inputs ที่แสดง Trailing เปิด + Pullback=0 และ Experts/Journal

รายการ	ค่า

ขั้นตอน
เริ่มหลังตรวจผล SHORT และตรวจความพร้อม Long Run แล้ว ตามหมายเหตุในไฟล์

เก็บการเปิด–จบ Basket หลายรอบ รวมช่วงก่อน/ระหว่าง/หลัง Session Block

เก็บ CSV และตรวจยอดกับ History ของ Symbol + Magic 99998

ผลคาดหวัง
ไม่มีคู่ซ้อนและไม่เติมขาที่หาย

ระยะเวลา: หากเป็นรอบ Report ใหม่ ต้องอย่างน้อย 24 ชั่วโมงและรอเงื่อนไขสร้าง Report ครบ “รันข้ามเที่ยงคืน” อย่างเดียวไม่พอ

Preset 18 — LONG รอบ Report 5 วัน
ไฟล์จริง: LONG_02_NORMAL_REPORT5_DRAFT.set

ค่าทั้งหมดเหมือน Preset 17 ยกเว้น ReportDays=5 และยังใช้ Magic 99998 เดียวกัน เอกสารระบุว่าเป็นโปรไฟล์อ้างอิงรอบรายงานปกติ ไม่ใช่ไฟล์ที่ต้องสลับเข้าออกระหว่าง Long Run ชุด 17

ขั้นตอนและผลคาดหวัง
หากต้องการตรวจรอบรายงานห้าวันจริง ให้ใช้ไฟล์นี้เป็นรอบทดสอบที่บันทึกแยกชัดเจน

ตรวจ Basket, Gates, Protection, Accounting และ State เช่นเดียวกับชุด 17

รายงานต้องเกิดเมื่อครบห้าวันจากเวลาเริ่มรอบที่ใช้อยู่ และ Basket ว่างพร้อมมี Tick

ถ้ารันเพียงคืนเดียว ตรวจได้เฉพาะเหตุที่เกิดในคืนนั้น ห้ามนับว่า Report ห้าวันผ่านแล้ว

ระยะเวลา: รอบใหม่ต้องครบ 120 ชั่วโมงขึ้นไปสำหรับการตรวจ Report ห้าวัน ไม่จำเป็นว่าต้องเป็นห้าวันที่มีการเทรดเต็มวัน แต่ตอนสร้างรายงานต้องมี Tick และ Basket ว่าง

ข้อสำคัญ: เพราะ 17 และ 18 ใช้ Magic เดียวกัน อย่าสลับไฟล์แล้วถือว่าเริ่ม Report ใหม่โดยอัตโนมัติ ต้องตรวจเวลาเริ่มรอบ State เดิมก่อนครับ

## ข้อยกเว้นสำคัญของ SHORT_11

SHORT_11 ไม่ควรถูกจัดว่า “ต้องนานกว่าชุด 14 เสมอ” ครับ:

- ถ้าเตรียม Fixture ของ Report พร้อมแล้ว ให้เลื่อน SHORT_11 มาทำก่อน SHORT_14 ได้ เพราะไม่ต้องรอราคาไปถึง BE Trigger
- ถ้ายังไม่มี Fixture ชุด 11 ไม่ใช่งานที่โหลด `.set` แล้วจบเร็วได้เอง เนื่องจากตั้ง ReportDays=1 และไม่ได้สร้างเหตุ Recovery/Failure อัตโนมัติ 

ดังนั้น ลำดับทำงานที่ผมแนะนำในสถานะปัจจุบันคือ:

```text
SHORT_15

```

ชุด 15–16 ทำขณะ Basket ว่าง ส่วนชุดที่ต้องรอราคา หากเหตุไม่เกิดในช่วงที่กำหนด ให้บันทึก `NOT_COVERED` ไม่จำเป็นต้องรอไม่มีกำหนด และไม่ถือว่าผ่านเพียงเพราะไม่มี Error ครับ



**ได้ครับ** คุณทดสอบจากชุดที่ใช้เวลาน้อยไปมากได้เลย ไม่จำเป็นต้องเรียงตามหมายเลขไฟล์ครับ หมายเลขไฟล์ใช้ระบุชุดทดสอบ ไม่ใช่คำสั่งว่าต้องรันตามลำดับ

สำหรับ SHORT_11–16 และ LONG 17–18 ใช้ลำดับที่จัดไว้ได้:

```text

→ SHORT_14 → SHORT_11 → LONG 17
→ LONG 18 เฉพาะเมื่อต้องการตรวจรอบรายงาน 5 วัน
```

## เงื่อนไขก่อนเปลี่ยนชุด

- จบ Position ของชุดก่อนหน้าให้เรียบร้อย โดยเฉพาะก่อนชุด 15–16 ซึ่งตั้งใจให้ EA เริ่มทำงานไม่สำเร็จ
- ถ้าชุดเดิมเปิด Auto Reopen ให้ปิด Auto ก่อนจัดการปิด Position เพื่อไม่ให้เปิดคู่ใหม่ระหว่างจบรอบ
- ตรวจ Magic จาก Inputs จริงทุกครั้ง ไม่ยึดชื่อโฟลเดอร์
- ไม่ลบ State เหมารวมเพื่อเริ่มชุดใหม่
- เก็บผลและหลักฐานแยกตามชื่อ Preset แม้ลำดับที่รันจะไม่ตรงหมายเลขไฟล์

## เงื่อนไขก่อนเริ่ม

1. ตั้ง Magic ให้เรียบร้อยก่อนเปิด Position อย่าเปลี่ยน Magic ของกราฟที่มี Position ค้าง เพราะ EA อาจไม่ติดตามไม้เดิมด้วย Magic ใหม่ [eaquantumlab](https://eaquantumlab.net/blog/expert-advisor-magic-number-explained)
2. ใช้หนึ่ง Instance ต่อ Symbol + Magic เท่านั้น เช่น XAUUSD + 99998 มีเพียงกราฟ A และ XAUUSD + 99997 มีเพียงกราฟ B
3. เก็บหลักฐานแยกตาม Magic ทั้ง Inputs, History, Log และ CSV ไม่รวมผลสองชุดเข้าด้วยกัน
4. อย่าคาดว่าโหลดไฟล์แล้วรอบ Report เริ่มใหม่เสมอ ต้องตรวจ State เดิมของแต่ละ Scope ด้วย ตามกลไกรอบรายงานที่ตรวจไว้ก่อนหน้านี้

- บัญชีอาจมี Buy 2 + Sell 2 รวมกันได้ หากแต่ละชุดเปิด Hedge ของตัวเองอยู่ ไม่ใช่คู่ซ้อนผิดเงื่อนไขโดยอัตโนมัติ ต้องตรวจ One Basket แยกต่อ Magic

- ชุด 17 ตรวจ Report รอบหนึ่งวัน ส่วนชุด 18 ตรวจรอบห้าวัน การรันพร้อมกันช่วยให้เริ่มนับเวลาไปพร้อมกันได้ แต่ไม่ได้ย่นรอบรายงานห้าวันให้สั้นลง 

ดังนั้นไม่ต้องรันชุด 17 จบแล้วค่อยเริ่มชุด 18 ครับ เปิดสองกราฟ แยก Magic ตั้งแต่ก่อนเริ่ม และเก็บผลแยกชุดได้เลย
