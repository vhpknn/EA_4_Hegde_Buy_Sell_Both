จากสถานะที่คุณแจ้ง **เหลือ 4 ช่วงใหญ่** ครับ: ปิดงาน Phase 4 → Short Test แบบรวม → Long Run ข้ามวัน → ตรวจผลและปิดงาน ไม่กลับไปทดสอบทีละ Patch อีก

## สถานะปัจจุบัน

```text
Patch ตามรายการ Phase 1–4F
→ รวมถึง 3 จุดจาก Final Audit ล่าสุด
→ คุณรายงานว่า Compile ผ่าน 0 errors / 0 warnings แล้ว

สิ่งที่ยังไม่ครบ:
→ ตรวจ Source รวมที่มี 3 จุดแก้ล่าสุด
→ Short Test
→ Long Run
→ สรุปผลการทดสอบจริง
```

ยังไม่มีเหตุผลให้เพิ่ม Manual Override A หรือ Trailing From Entry B ในรอบนี้ ทั้งสองอย่างเก็บไว้สำหรับเวอร์ชันอนาคตตามที่ตกลงกันครับ

## Phase 4 — ปิดงานพัฒนาและล็อก Source

### งานที่เหลือ

1. ตรวจว่า Source ชุดล่าสุดรวมสามจุดสุดท้ายแล้ว:
   - Capital ตรวจผลการอ่าน History Property
   - ติดตั้ง SL ที่หายได้แม้กำไรเลย BE Trigger
   - Rollback รอบสุดท้ายคืนผลถูกต้องเมื่อ Basket ว่างแล้ว

2. ตรวจการประกอบทั้งระบบ:
   - Include และจุดเรียกฟังก์ชันตรงกัน
   - ไม่มีฟังก์ชันซ้ำหรือการเรียกชื่อเก่าค้าง
   - ลำดับ Protect → Report → Engine → Panel ถูกต้อง
   - คำสั่งเปิดถูก Gate แต่ Protection และคำสั่งปิดไม่ถูกหยุดตาม
   - Source ที่ Compile เป็นไฟล์ชุดเดียวกับที่จะนำไปทดสอบ

3. เก็บ Comment/คำอธิบายที่ยังไม่ตรงกับโค้ด โดยไม่เปลี่ยนกลยุทธ์เพิ่ม

4. ล็อกขอบเขตและข้อจำกัดของรุ่นทดสอบ เช่น หนึ่ง Instance ต่อ Symbol + Magic และกรณี State/Ticket ที่ยังไม่รองรับครบ

### จุดจบ Phase 4

```text
ข้อค้นพบที่ต้องแก้ถูกเก็บครบ
→ Compile รอบรวมผ่าน
→ Commit + Push รวมหนึ่งครั้ง
→ ตรวจ Source จาก SHA เดียวกัน
→ ล็อกเป็น Baseline สำหรับทดสอบ
```

ถ้าพบข้อบกพร่องจากการตรวจรวม จะรวมเป็นชุดแก้ก่อนล็อก Baseline ไม่สลับไปเปิด Order ทดสอบหลังแก้แต่ละจุด

## Phase 5 — Short Test แบบครบชุด

### งานเตรียมก่อนเริ่ม

- ทำ Preset ทดสอบแยกจากค่ารันยาว
- ตรวจว่าค่า Lot และระยะ Protection ใช้กับ Symbol ที่ทดสอบได้
- กำหนด Checklist, ผลที่คาดหวัง และหลักฐานที่จะเก็บให้ครบก่อนเริ่ม
- ใช้ Source เวอร์ชันเดียวตลอดชุดทดสอบ

### ขอบเขตที่ต้องตรวจในชุดเดียว

| หมวด | รายการตรวจ |
|---|---|
| เปิดและปิด Order | เปิดคู่, Volume ตรงกัน, SL ทั้งสองไม้, ปิดรายฝั่ง/ทั้งหมด |
| One Basket | HEDGE ซ้ำถูก Block, BUY/SELL เดี่ยวถูก Block, ไม่เปิดขาที่หายกลับมา |
| Order failure | เปิดคู่ไม่ครบ, Rollback, ปิด/Modify ไม่สำเร็จ |
| Protection | Cut Loss, BE Fixed/Trailing, RR, Armed Trailing, SL ไม่คลายกลับ |
| Restart/State | Restore Best Profit และ Cycle, Cleanup, Legacy Import ตามเงื่อนไข |
| Entry Gate | Capital, Session, Timeout, Spread และ Report |
| Capital | REFILL, Auto-Lot, ทุนหมด, ข้อมูลอ่านไม่ได้ |
| Report | เขียน CSV, TOTAL/Metadata, Report Recovery, ไม่เปิดคู่ก่อน Report เสร็จ |
| Inputs/Panel | ค่าผิดถูกปฏิเสธ, LOCKED/N/A/สถานะต่าง ๆ แสดงตรงกับการทำงาน |

### วิธีดำเนินการ

```text
เตรียม Checklist ให้ครบ
→ รันทดสอบครบชุด
→ เก็บ Log / ภาพ / CSV / Preset รวม
→ ไม่หยุดส่งผลให้ผมตรวจหลังทุกข้อ
```

การแบ่ง Checklist เป็นหมวดมีไว้จัดระเบียบ ไม่ใช่แยกเป็นรอบพัฒนาหรือรอคำตอบทีละฟีเจอร์

## Phase 6 — Long Run ข้ามวัน

ใช้ Baseline เดียวกับ Short Test โดยเปลี่ยนเป็น Preset ระยะใช้งานจริง ไม่เพิ่มฟีเจอร์ระหว่างรัน

สิ่งที่ต้องติดตาม:

```text
- การเปิด/จบ Basket หลายรอบ
- Session เปิด–ปิดและ Timeout
- Protection และ State ที่คงอยู่ต่อเนื่อง
- Restart/การเชื่อมต่อและความเปลี่ยนแปลงข้ามวัน
- ทุนเสมือน, REFILL, Lot และ Cycle
- CSV/Report Gate
- Error, Log ซ้ำผิดปกติ และ Position ที่ค้างผิดเงื่อนไข
```

เก็บผลเป็นชุดเดียว ไม่ต้องรายงานทุกครั้งที่ Order เปิดหรือปิด ส่วนเหตุผิดปกติร้ายแรงต้องบันทึกเป็นข้อยกเว้นของการรัน ไม่ปล่อยให้หายไปในผลรวม

## Phase 7 — ตรวจผลรวมและปิดงาน

รวบรวมหลักฐานจาก Short Test และ Long Run:

```text
Source SHA / ผล Compile
Preset ที่ใช้จริง
Experts + Journal Logs
ภาพ Position และ Panel
CSV
Checklist พร้อมผลและเวลาที่เกิดเหตุ
```

จากนั้นสรุป:

- ข้อใดผ่านพร้อมหลักฐาน
- ข้อใดไม่ผ่านหรือยังไม่ได้ทดสอบ
- ปัญหาใดเป็นโค้ด, Inputs, สภาพแวดล้อม หรือข้อจำกัดที่ระบุไว้
- หากต้องแก้ ให้รวมเป็นชุดแก้และกำหนดขอบเขตทดสอบซ้ำ
- เมื่อผ่านเกณฑ์ที่ตกลงกัน จึงล็อกเวอร์ชันและ Preset สุดท้าย
