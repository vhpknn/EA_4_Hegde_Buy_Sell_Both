## 8. วงจรการทำงานต่อหนึ่งงาน
1. เลือก Finding หนึ่งข้อ เขียนรายงานตามหัวข้อ 7
2. Commit สถานะปัจจุบัน แล้วสร้าง Branch ใหม่
3. เขียนหรือยืนยัน Test ที่ล้มก่อนแก้
4. ให้ AI แก้เฉพาะขอบเขตที่อนุญาต
5. รันชุดตรวจทั้งหมด และตรวจ Diff เอง (ดูส่วนที่ถูกลบ)
6. ผ่านทั้งหมด = รวม Branch + Tag เวอร์ชัน / มีข้อใดล้ม = ย้อนกลับทั้งหมด ห้ามแก้ซ้อน
7. แก้ไม่ผ่านเกิน 2 รอบ = หยุด ทบทวนสเปก

## 10. เช็กลิสต์ก่อนส่งตรวจ
- [ ] ทุกกฎมี ID, เกณฑ์ตัวเลข และตัวตรวจ
- [ ] ทุกกฎมีหลักฐานครบทั้งสองฝั่ง หรือระบุ "ยังไม่ทดสอบ"
- [ ] ไฟล์หลักฐานดิบเก็บครบพร้อม Hash และไม่ถูกแก้ไข
- [ ] รายงานสร้างจากหลักฐานดิบ ย้อนกลับถึงบรรทัดต้นทางได้
- [ ] ทุก Finding ปิดแล้วหรือมีเหตุผลที่ยอมรับได้บันทึกไว้
- [ ] เวอร์ชันโค้ด ชุดสเปก และชุดตรวจ ตรงกันและติด Tag
