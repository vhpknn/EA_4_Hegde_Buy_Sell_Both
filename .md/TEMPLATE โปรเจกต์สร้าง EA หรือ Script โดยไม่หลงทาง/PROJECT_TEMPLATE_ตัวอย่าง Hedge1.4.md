# เทมเพลตโปรเจกต์ EA (ตัวอย่างจาก Hedge1.4 Short Test)

> สถานะข้อความ: [ยืนยันแล้ว] = ตรวจกับ Log จริงแล้ว | [ต้องยืนยัน] = อนุมานจาก Log ผู้ใช้ต้องตัดสิน

---
## 0. กติกาโปรเจกต์ (Constitution) - เขียนครั้งเดียว ใช้ตลอด
- C-01 ทุกกฎต้องมีหลักฐานทั้ง Buy และ Sell อย่างน้อยฝั่งละหนึ่งครั้ง ฝั่งที่ยังไม่เกิดเหตุ = "ยังไม่ได้ทดสอบ" ไม่ใช่ "ผ่าน"
- C-02 หนึ่งการแก้ = หนึ่ง Finding (DEV-xxx) ห้ามแตะโค้ดที่ไม่เกี่ยวกับ Finding นั้น
- C-03 ห้ามเพิ่มฟีเจอร์ที่ไม่อยู่ในสเปก (ดู Non-goals)
- C-04 EA ไม่เขียน Log วิเคราะห์เอง ใช้ Log ของ MT5 + Python ภายนอก
- C-05 ก่อนแก้ ต้อง Commit สถานะที่ผ่านแล้ว หลังแก้ต้องรันชุดตรวจ "ทั้งหมด" ข้อที่เคยผ่านแล้วล้ม = ย้อนกลับทั้งหมด ห้ามแก้ซ้อน
- C-06 ถ้าแก้ไม่ผ่านเกิน 2 รอบ ให้หยุดและทบทวนสเปก ไม่ให้ AI ลองต่อ
- C-07 ทุกรอบเก็บ Log ดิบ + SHA-256 ไม่แก้ไฟล์ดิบ

## 1. Non-goals (สิ่งที่ไม่ทำ)
- ไม่ประเมินความสามารถทำกำไรของกลยุทธ์
- ไม่ทดสอบเงินจริง (Demo เท่านั้นจนกว่าปิด Phase ทดสอบ)
- ไม่ทำ Log วิเคราะห์ใน EA

## 2. สเปก (Spec) - ตัวอย่างกฎ
หน่วย: XAUUSD 1 Point = 0.01 ราคา

| ID | กฎ | เกณฑ์ตรวจรับ | สถานะ |
|---|---|---|---|
| R-OPEN-01 | เปิดคู่ Buy + Sell พร้อมกันด้วยคำสั่งตลาด ใส่ SL ตั้งต้นที่ ราคาขอ -/+ 70 Points | Journal: คำสั่ง market buy และ market sell ห่างกัน < 1 วินาที, SL ตั้งต้นเท่ากับ ask-0.70 (Buy) และ bid+0.70 (Sell) | [ยืนยันแล้ว] 13 รอบใน Preset 05 |
| R-CUT-01 | หลัง Fill ปรับ SL เป็น ราคา Fill -/+ 70 Points | modify แรกหลัง Fill: SL = Fill-0.70 (Buy) / Fill+0.70 (Sell) | [ยืนยันแล้ว] ยกเว้น DEV-002 |
| R-CUT-02 | ถ้า SL ใหม่ตั้งไม่ได้ (Invalid stops) ต้องไม่ปล่อยให้ระยะขาดทุนเกิน 70 Points | ทุกขาต้องมี SL ห่าง Fill <= 70 Points ภายใน N ms [ต้องยืนยัน N และวิธีจัดการ] | [ไม่ผ่าน] ดู DEV-002 |
| R-BE-01 | หลังเริ่ม BE SL ห้ามขยับไปทางเสี่ยงกว่าเดิม | ลำดับ SL ของแต่ละ Ticket ไม่ถอยหลัง | [ยืนยันแล้ว] |
| R-BE-02 | เริ่มล็อกเมื่อกำไร >= 120 Points ล็อก = 20% ของกำไรที่ปัดลงตาม Step 10 | กำไร 125 -> ล็อก 24, 142 -> 28, 188 -> 36, 307 -> 60 | [ยืนยันแล้ว] |
| R-TRAIL-01 | Trailing TP: เริ่มติดตามเมื่อกำไร >= 120 ปิดด้วยคำสั่งตลาดเมื่อกำไรลดจาก Best ตั้งแต่ 50 Points | Best 307 ปิดที่ 256, Best 234 ปิดที่ 180, Best 188 ปิดที่ 103 | [ยืนยันแล้ว] ครั้งที่ 3 ย่อ 85 (ดู O-02) |
| R-BASE-01 | Baseline รอบถัดไป = Baseline เดิม + ผลรวมสุทธิของคู่ที่ปิดแล้ว | ผลดีลของ 12 รอบตรงทุกค่า | [ยืนยันแล้ว] |
| R-END-01 | จบรอบ: ไม่มี Position ค้าง EA ถูกถอดแล้ว | Journal: ขาสุดท้ายถูกปิด, Experts: removed | [ยืนยันแล้ว] |

ข้อที่ต้องให้ผู้ใช้ตัดสินก่อนใช้เป็นเกณฑ์ Audit: ค่า N ใน R-CUT-02, ความหมายของ "ย่อตั้งแต่ 50" เมื่อมีช่วงข้อมูลเว้น (O-02), พฤติกรรมที่ต้องการเมื่อ Slippage ทำให้ตั้ง SL 70 ไม่ได้

## 4. แม่แบบรายงานการเบี่ยงเบน (ส่งให้ AI แก้)

[DEV-002] R-CUT-02 ตั้ง SL หลัง Fill ไม่สำเร็จเมื่อ Slippage สูง
- เวอร์ชัน / Preset / Magic : Hedge1.4 / SHORT_05 / 99905
- ข้อกำหนดที่คาดหวัง : ขา Buy ต้องมี SL ห่างจาก Fill ไม่เกิน 70 Points
- สิ่งที่เกิดจริง : 08:04:02.240 Buy Fill 4147.92 (ขอ 4147.51 แย่กว่า 41 Points) SL ตั้งต้น 4146.81 ห่าง 111 Points; modify -> 4147.22 ถูกปฏิเสธ 4 ครั้ง [Invalid stops]; สำเร็จ 08:04:03.639 (ผ่านไป 1.4 วินาที); ขานั้นถูก SL ปิดที่ 4147.22 เวลา 08:04:04.021
- ผลกระทบ : ระยะเสี่ยงจริงเกินที่กำหนดชั่วคราว (ผลขาดทุนจริง -0.70 ไม่เกิน)
- ขอบเขตที่ห้ามแก้ : R-BE-*, R-TRAIL-*, R-BASE-01 (ผ่านแล้ว)
- เกณฑ์ผ่านหลังแก้ : ชุดตรวจทั้งหมดผ่านเท่าเดิม + R-CUT-02 ผ่านใน Preset 04/05 รันซ้ำ
- ห้าม : เพิ่มฟีเจอร์ใหม่, เปลี่ยน Log, แก้ไฟล์อื่นนอกฟังก์ชัน ModifySL

[F-01] Log ซ้ำ 'skipped as it changes nothing' 16 ครั้ง - ไม่กระทบเทรด (ความรุนแรงต่ำ) ตัดสินแยก

## 5. วงจรการทำงานต่อหนึ่งงาน
1. เลือก Finding หนึ่งข้อ -> เขียนรายงานตามแม่แบบ
2. Commit สถานะปัจจุบัน + Branch ใหม่
3. เขียน/ยืนยัน Test ที่ล้มก่อนแก้
4. ให้ AI แก้เฉพาะขอบเขตที่อนุญาต
5. รันชุดตรวจทั้งหมด + ตรวจ Diff เอง (ดูส่วนที่ถูกลบ)
6. ผ่าน = รวม Branch + Tag เวอร์ชัน / ไม่ผ่าน = ย้อนกลับทั้งหมด
